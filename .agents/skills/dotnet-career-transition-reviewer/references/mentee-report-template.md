# Session mentoring feedback

Audience: Mentee. Generate only when explicitly requested, independently from selected learner-safe evidence. Never copy private assessments, link private paths, include personnel hypotheses or provide assignment implementations/test setups.

## Review metadata

Mentee identifier, session/part, repository, branch/full SHA, uncommitted inclusion, assignment/template reference, scope and date. Omit sensitive internal details.

## Strengths

Specific code-backed strengths and why they help.

## Assignment compliance and review coverage

Include learner-safe coverage: total active criteria, Met/Partially Met/Not Met/Not Verified counts, per-criterion source/evidence/status, inspected paths and incomplete/unverified areas. Counts reconcile. Static inspection does not establish runtime success. Do not add technical findings through matrix comments.

## Things to reconsider (at most five)

Order critical security/correctness first, then reliability/tests, design, readability and style. Each finding: ID, severity, Must-fix/Optional, category, known path/line, observed implementation/evidence, concrete impact, assignment linkage, applicable version-appropriate documentation URL/explanation and one focused coaching direction. Explain the concept and a useful hint, never an assignment solution.

If no findings qualify, say so. For significant overflow state total/omitted/critical-omitted counts. Say the list is incomplete and further mentor discussion is needed without linking/quoting private material. Never silently omit critical issues; full significant overflow is retained privately.

## Learning focus

Separate general engineering, C# language/runtime and .NET ecosystem understanding and relevant priorities. Previous-stack comparisons require supplied background and evidence. Avoid future-topic overload; at most two meaningful questions across the feedback.

## Verification and limitations

Inspected/excluded areas, unverified behavior, builds/tests status, supplied output, actual Learn MCP verification or disclosed fallback, assignment ambiguities. Limited review is not a clean bill of health.

## Suggested next step

One concrete learner-owned action.
