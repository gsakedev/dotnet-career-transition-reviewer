## Strengths

Specific code-backed positive choices and practical benefits. Separate general engineering, C# language/runtime and ecosystem evidence.

## Assignment compliance and coverage

Include completed coverage template or a private relative link. State total active criteria, all four status counts, inspected/partial/uninspected paths, ambiguities and execution limits. Never conceal extra technical findings in matrix comments.

## Technical evaluation

For functional correctness, C#/.NET fundamentals, architecture/SOLID, patterns, reliability/testing, security/performance and maintainability: summarize evidence, applicable stage, confidence and limitations. Mark irrelevant dimensions Not Applicable. Explain useful alternatives/trade-offs without assignment solutions.

## Career-transition evaluation

Separate demonstrated general engineering, C# language/runtime and .NET ecosystem knowledge. Previous-stack comparisons need supplied background and relevant evidence. Distinguish observed behavior from misconception hypotheses. Progress claims need identified baseline code/reports and allowance for changed requirements.

## Prioritized mentoring findings (maximum five)

Each selected finding contains:
- ID, severity (Critical/High/Medium/Low), Must-fix/Optional and category.
- Known path/line and exact target.
- Observed implementation and supporting code/call-path evidence.
- Reachable triggering scenario and why it matters.
- Applicable assignment criterion/source or explicit non-requirement rationale.
- Documentation URL, actual version, behavior/requirement/recommendation/convention/preference classification, applicability and verification method.
- One coaching question/improvement direction.
- Mentor explanation and alternatives without implementation-ready solutions.

If none qualify, say so. State total significant findings, normal-report count, overflow count and critical-omitted count. A capped list does not establish readiness.

## Complete significant findings (mentor-only)

Retain all significant validated overflow with the same evidence fields. Reference selected IDs instead of duplicating them. Critical overflow explicitly requires mentor triage before treating review as complete. Unvalidated suspicions belong in verification questions, not findings.

## Mentoring summary

Key strengths, highest-priority improvements, at most two meaningful discussion questions and targeted learning priorities. No arbitrary scoring or unsupported personnel conclusions.

## Verification

Inspected/excluded material; static versus learner-supplied/approved execution evidence; builds/tests status (normally Not executed); actual Learn retrievals/URLs or disclosed fallback; target-drift check; assumptions/conflicts/risks. Tests inspected are not tests passed.

## Suggested next step

One small, concrete learner-owned action.
